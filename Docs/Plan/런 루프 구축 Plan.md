# 로그라이크 런 루프 구축

## 계획 개요

- 계획명 : 런 루프 구축
- 계획 유형 : 대규모 기능 추가
- 목적 :
    - 단일 전투 프로토타입을 "시작 → 맵 → 전투 → 보상 → 보스 → 클리어/게임오버"로 이어지는 최소 런 구조로 확장
    - 이후 상점, 휴식, 유물 등을 붙일 수 있는 런 기반 마련
- 작업 범위 :
    - 기존 코드 정리
    - 전투 시스템 보강 (방어도, 상태이상, 적 행동 패턴, 다수 적)
    - 런 상태 관리 및 게임 흐름
    - 전투 보상, 맵 진행, 보스

## 현황 분석 (As-is)

- `Test.unity` 단일 씬에서 전투 1회만 진행
- 카드 : `CardData`(SO) + `CardEffect`(SO) 조합. 효과 3종(피해/회복/중독), 카드 6종
- 덱 순환 : `CardManager`가 `startingCards`로 매 전투 덱을 새로 생성, 덱 → 손패 → 버림 더미 → 재셔플
- 턴 : `TurnManager`가 플레이어 턴(에너지 회복, 5장 드로우) → 적 턴(중독 처리 → 고정 피해 공격) 반복
- 에너지 : 최대 3, 코스트 부족 카드 비활성 표시
- 전투 결과 : `BattleManager`가 체력 0 기준 승리/패배 판정 후 텍스트 표시
- 적 : `Enemy` 1체 고정, 공격력 고정(`attackDamage`), 중독 수치를 `Enemy` 내부에서 직접 관리
- 테스트성 기능 : 카드 강화 버튼(`CardSelectionManager`, 첫 효과 +3), 수동 드로우 버튼(`CardDrawController`)
- 없음 : 방어도, 적 의도 표시, 다수 적/타겟 지정, 전투 간 데이터 유지, 보상, 맵, 메뉴/게임오버 흐름
- 확인된 문제 (코드 열람 기준, 미검증)
    - `Player.Start()`에서 체력을 `maxHealth`가 아닌 `30`으로 고정 초기화
    - `CardInstance.cs`의 미사용 `using NUnit.Framework;` → 빌드 시 오류 가능
    - private 필드가 `coding-conventions.md`의 `_camelCase` 규칙과 불일치
    - 카드명 오타 : `Posion 일격`

## 목표 (To-be)

- 메인 메뉴에서 런을 시작하고, 맵에서 노드를 골라 전투를 이어간다
- 체력과 덱이 전투 사이에 유지된다
- 전투 승리 시 카드 3장 중 1장을 골라 덱에 추가할 수 있다
- 적이 다음 행동(의도)을 미리 보여주고, 정해진 패턴대로 행동한다
- 플레이어와 적 모두 방어도를 사용할 수 있다
- 한 전투에 여러 적이 등장할 수 있고, 공격 카드는 대상을 지정한다
- 최종 노드의 보스를 처치하면 클리어, 체력이 0이 되면 게임오버 화면으로 이동한다

## 시스템 설계

| 시스템 | 주요 역할 | 연관 시스템 | 구현 방향 |
|---|---|---|---|
| Run System | 런 상태(체력, 덱, 현재 층) 보관 및 흐름 제어 | Battle, Map, Reward, Flow | 전투·맵 사이에서 유지되는 런 데이터 구조 추가 |
| Flow System | 메인 메뉴, 맵, 전투, 클리어/게임오버 화면 전환 | Run | 화면별 씬 분리 및 씬 전환 구조 추가 |
| Battle System | 전투 시작/종료, 승패 판정 | Turn, Card, Enemy, Run | 기존 `BattleManager` 확장, 결과를 Run으로 전달 |
| Turn System | 턴 진행 | Battle, Enemy, Card | 기존 `TurnManager`를 다수 적 처리 구조로 확장 |
| Card System | 덱/손패/버림 더미, 카드 사용 | Run, Battle, Status | 런 덱을 받아 전투 덱을 구성하도록 변경 |
| Enemy System | 적 데이터, 행동 패턴, 의도 표시 | Battle, Turn, Status | 적 데이터(SO)와 행동 패턴 구조 추가 |
| Status System | 방어도, 중독 등 상태 관리 | Card, Enemy, Player | 상태를 공통 구조로 분리 |
| Reward System | 전투 보상 카드 선택 | Run, Card | 보상 후보 생성 및 덱 추가 |
| Map System | 노드 생성, 진행 경로 선택 | Run, Flow, Battle | 노드 종류 : 일반 전투 / 보스 |

### 기술 및 설계 방향

- 런 데이터 유지 : 씬 분리 + `DontDestroyOnLoad` 런 관리자 (확정)
- 적 행동 : 적 데이터(SO)에 행동 목록을 두고 순서/조건에 따라 선택. 기존 `CardEffect` 재사용 가능 여부 검토
- 상태이상 : 중독을 `Enemy` 내부 필드에서 분리해 플레이어와 적이 함께 쓰는 구조로 검토
- 카드 효과 대상 : 현재 `Execute(Player, Enemy, int)` 시그니처는 단일 적 전제. 다수 적과 대상 지정에 맞춘 전달 방식 검토
- 맵 : 고정 데이터 맵으로 시작, 절차적 생성은 이후 확장 검토 (확정)
- 대상 지정 : 카드 클릭 후 적 클릭 (확정)
- 이벤트 기반 UI 갱신 등 기존에 쓰던 방식은 유지

### 기존 시스템 영향

- `CardEffect` 및 효과 3종 : 대상 전달 방식 변경 시 시그니처 수정
- `Enemy` : 고정 공격 → 패턴 기반 행동, 중독 로직 분리, 의도 UI 추가
- `Player` : 체력을 런 상태와 연동, 방어도 추가
- `TurnManager` : 단일 `enemy` 참조 → 적 목록 처리
- `BattleManager` : 단일 적 기준 승리 판정 → 전체 적 기준, 결과를 보상/게임오버 흐름으로 연결
- `CardManager` : `startingCards` 고정 덱 → 런 덱 기반 초기화
- `CardView` / `CardSpawner` : 대상 지정 방식 반영, `Initialize` 매개변수 구조 영향
- `CardSelectionManager`, `CardDrawController` : 디버그 전용으로 분리해 유지 (확정)
- 기존 단일 전투 동작은 각 단계 후에도 유지되어야 함

## 검증 계획

### 단계별 검증

- [ ] 0단계 후 기존 단일 전투가 이전과 동일하게 동작하고, 빌드 시 컴파일 오류가 없음
- [ ] 방어도가 피해를 먼저 흡수하고, 턴 시작 시 규칙대로 초기화됨
- [ ] 중독이 플레이어와 적 모두에게 같은 규칙으로 적용됨
- [ ] 적의 의도 표시와 실제 행동이 일치함
- [ ] 여러 적 중 지정한 대상에게만 카드 효과가 적용되고, 모든 적 처치 시 승리함
- [ ] 전투 후 체력과 덱이 다음 전투로 유지됨
- [ ] 보상으로 고른 카드가 다음 전투 덱에 포함됨
- [ ] 맵에서 연결된 노드만 선택 가능하고, 선택한 노드의 전투로 진입함

### 통합 검증

- [ ] 메인 메뉴 → 맵 → 전투 → 보상 → … → 보스 → 클리어까지 끊김 없이 진행
- [ ] 런 도중 사망 시 게임오버 화면으로 이동하고, 새 런을 시작할 수 있음
- [ ] 새 런 시작 시 이전 런의 체력·덱·맵 상태가 남지 않음
- [ ] 유니티 에디터에서 컴파일 에러 및 Error, Warning 로그가 발생하지 않음
