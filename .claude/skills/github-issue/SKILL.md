# Github Issue 등록

> 이 스킬은 이슈 등록의 **절차**와 **멘트 규칙**만 정의한다.
>
> 섹션별 작성 규칙은 `Docs\Documentation\Github Issue Rule.md`, 양식은 `Docs\Template\Issue Template.md`가 단일출처다. 이 스킬에 규칙을 옮겨 적지 않는다.
>
> 이슈 단계의 진입/종료 조건은 `Docs\Claude\WorkflowRules.md`의 `2. Github Issues`를 따른다.

---

## 절차

### 1. 권유

- `WorkflowRules.md` `2. Github Issues`의 권유 조건에 해당하면, 아래 `멘트 규칙 - 권유`에 따라 권유한다.
- 사용자가 직접 이슈 작성을 요청한 경우 이 단계를 생략한다.
- 사용자가 거절하면 스킬을 종료하고, 이슈 생략 결정으로 처리한다.

### 2. 규칙 문서 읽기

- 아래 두 문서를 읽는다.
    - `Docs\Documentation\Github Issue Rule.md` (전체 섹션)
    - `Docs\Template\Issue Template.md` (`이슈 작성 템플릿`)

### 3. 정보 수집

- `Github Issue Rule.md`의 `2. 배경 / 목적`에 따라 사용자에게 배경/목적을 질문한다.
    - 답을 받지 못하면 이슈 작성을 거부한다.
- 대화와 코드로 확인 가능한 정보는 다시 묻지 않는다.
- 연관 이슈 확인이 필요하면 `gh issue list`로 조회한다. (`6. 특이사항` 작성 목적)

### 4. 초안 작성

- `Issue Template.md` 양식에 `Github Issue Rule.md`의 섹션별 규칙(`1. Title` ~ `6. 특이사항`)을 적용해 작성한다.
- 라벨은 `Github Issue Rule.md`의 `7. 기타 - Label`에서 하나를 고른다.

### 5. 승인 요청

- 아래 `멘트 규칙 - 승인 요청`에 따라 초안을 제시하고 승인을 받는다.
- 수정 요청이 있으면 반영한 초안을 다시 제시한다.

### 6. 등록

- 승인 후 등록한다.
    1. `gh label list`로 라벨 존재를 확인하고, 없으면 `gh label create`로 만든다.
    2. `gh issue create --title "..." --label "..." --body-file <임시파일>`로 등록한다. 본문은 스크래치패드 임시파일로 전달한다.
- 등록 결과로 이슈 번호와 URL을 한 줄로 보고한다.

**종료 조건** : 이슈 번호 확보 또는 사용자의 이슈 생략 결정

## 멘트 규칙

### 공통

- 인사말, 서론, 맺음말을 쓰지 않는다.
- 이미 확정된 정보를 다시 묻거나 반복하지 않는다.
- 질문은 한 번에 모아서 하고, 번호를 붙인다.

### 권유

- 2줄 이내. `이유 1줄` + `질문 1줄`.
- 예시:
    ```markdown
    `PlayerController`의 구조가 바뀌는 작업이라 이슈 등록을 권장합니다.
    이슈를 작성할까요?
    ```

### 정보 수집

- 사용자에게 받아야 하는 항목만 번호 목록으로 묻는다.
- 예시:
    ```markdown
    이슈 작성에 아래 정보가 필요합니다.
    1. 배경 / 목적 : 이 작업이 필요한 이유는 무엇인가요?
    2. 연관 이슈가 있나요? (없으면 생략)
    ```

### 승인 요청

- `요약 블록` → `본문 전문` → `질문 1줄` 순서로 제시한다.
- 요약 블록은 아래 4개 항목만 적는다.
- 예시:
    ````markdown
    **이슈 초안**
    - 제목 : [Feat] 플레이어 이동 구현
    - 라벨 : Feature
    - 목표 : 입력에 따른 플레이어 이동
    - 작업 파일 : 생성 1 / 수정 2

    ```markdown
    (Issue Template 양식의 본문 전문)
    ```

    등록할까요?
    ````
