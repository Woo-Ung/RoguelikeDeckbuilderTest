# Github PR 생성

> 이 스킬은 PR 단계의 **절차**와 **멘트 규칙**만 정의한다.
>
> 섹션별 작성 규칙은 `Docs\Documentation\Github PR Rule.md`, 양식은 `Docs\Template\PR Template.md`가 단일출처다. 이 스킬에 규칙을 옮겨 적지 않는다.
>
> 단계의 진입/종료 조건은 `Docs\Claude\WorkflowRules.md`의 `7. Commit / Push` ~ `9. 병합, 브랜치 파기`를 따른다.

---

## 조직 지침 제한

> 현재 조직 지침상 Git 기능은 **PR 생성만** 허용된다. 아래 `[제한]` 표시가 붙은 절차는 요청을 받아도 수행하지 않는다.
>
> 조직 지침이 변경되면 해당 절차의 `[제한]` 표시만 제거한다.

- `[제한]` 절차를 요청받으면 `멘트 규칙 - 제한 안내`에 따라 거부하고, 사용자가 직접 수행할 명령을 안내한다.
- PR 생성에 필요한 **읽기 전용** 조회(`git branch --show-current`, `git status`, `git log` 등)는 허용한다.

---

## 절차

### 1. Commit / Push `[제한]`

- `WorkflowRules.md` `7. Commit / Push`를 따른다.
- 사용자가 Push 완료를 보고하면 `2. 규칙 문서 읽기`로 넘어간다.

### 2. 규칙 문서 읽기

- 아래 두 문서를 읽는다.
    - `Docs\Documentation\Github PR Rule.md` (전체 섹션)
    - `Docs\Template\PR Template.md` (`PR 작성 템플릿`)

### 3. 정보 수집

- 읽기 전용 조회로 아래를 확인한다.
    - 현재 브랜치 : `git branch --show-current`
    - Push 여부 : `git status`로 원격과의 차이 확인. Push되지 않은 커밋이 있으면 `1. Commit / Push`로 돌아간다.
    - 변경 파일 : `git diff --stat <대상 브랜치>...HEAD` (`4. 작업 내용` 작성 목적)
- 관련 이슈가 있으면 `gh issue view <번호>`로 내용을 확인한다. (`2. 중점적으로 살펴볼곳`, `7. 이슈 닫기` 작성 목적)
- 대화와 코드로 확인 가능한 정보는 다시 묻지 않는다.
- 확인되지 않은 항목만 사용자에게 묻는다.
    - 병합 대상 브랜치
    - 관련 이슈 / 닫을 이슈 번호
    - `5. 구현 예시` : **생략**할지, PR 생성 후 **직접 첨부**할지

### 4. 초안 작성

- `PR Template.md` 양식에 `Github PR Rule.md`의 섹션별 규칙(`1. Title` ~ `7. 이슈 닫기`)을 적용해 작성한다.
- `5. 구현 예시`
    - 생략 : 섹션에 `- 생략`으로 적는다.
    - 직접 첨부 : 섹션에 첨부할 내용만 적고, 이미지는 비워 둔다.
- `6. 리뷰 요구 사항(선택)`은 해당 내용이 없으면 섹션째 뺀다.

### 5. 승인 요청

- 아래 `멘트 규칙 - 승인 요청`에 따라 초안을 제시하고 승인을 받는다.
- 수정 요청이 있으면 반영한 초안을 다시 제시한다.

### 6. 생성

- 승인 후 생성한다.
    - `gh pr create --base <대상 브랜치> --head <현재 브랜치> --title "..." --body-file <임시파일>`
    - 본문은 스크래치패드 임시파일로 전달한다.
- 생성 결과로 PR 번호와 URL을 한 줄로 보고한다.
- `5. 구현 예시`를 직접 첨부하기로 했다면, PR 페이지에서 본문을 편집해 이미지를 첨부하도록 안내한다.

**종료 조건** : PR 생성 완료

### 7. 병합, 브랜치 파기 `[제한]`

- `WorkflowRules.md` `9. 병합, 브랜치 파기`를 따른다.
- 사용자가 병합 및 브랜치 파기 완료를 보고하면 스킬을 종료하고 `10. Issue Close`로 넘어간다.

## 멘트 규칙

### 공통

- 인사말, 서론, 맺음말을 쓰지 않는다.
- 이미 확정된 정보를 다시 묻거나 반복하지 않는다.
- 질문은 한 번에 모아서 하고, 번호를 붙인다.

### 정보 수집

- 사용자에게 받아야 하는 항목만 번호 목록으로 묻는다.
- 예시:
    ```markdown
    PR 작성에 아래 정보가 필요합니다.
    1. 병합 대상 브랜치 : Develop이 맞나요?
    2. 닫을 이슈 번호가 있나요? (없으면 생략)
    3. 구현 예시 : 생략할까요, PR 생성 후 직접 첨부할까요?
    ```

### 승인 요청

- `요약 블록` → `본문 전문` → `질문 1줄` 순서로 제시한다.
- 요약 블록은 아래 5개 항목만 적는다.
- 예시:
    ````markdown
    **PR 초안**
    - 제목 : [Feat] 플레이어 이동 구현
    - 브랜치 : Feature/player-move → Develop
    - 관련 이슈 : #12 (Closes #12)
    - 구현 예시 : 직접 첨부
    - 변경 파일 : 생성 1 / 수정 2

    ```markdown
    (PR Template 양식의 본문 전문)
    ```

    생성할까요?
    ````

### 제한 안내

- 2줄 이내. `거부 사유 1줄` + `직접 수행할 명령 1줄`.
- 예시:
    ```markdown
    Push는 현재 조직 지침에 의해 수행할 수 없습니다.
    직접 `git push origin Feature/player-move` 후 완료되면 알려주세요.
    ```
